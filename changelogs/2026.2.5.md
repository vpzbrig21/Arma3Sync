# Arma3Sync `2026.2.5`

This release continues the modernization of Arma3Sync from the original
1.7.107 codebase. It focuses on reliable updates, safer file handling,
repository compatibility and exporting Workshop modsets for the official Arma
3 Launcher.

## Highlights

- Added export of selected Workshop modsets as valid Arma 3 Launcher HTML
  presets.
- Workshop metadata is read from each mod's `meta.cpp`, including Workshop ID
  and display name.
- Added centralized Creator DLC metadata and a local AppData metadata store
  for missing Workshop metadata recovery.
- Preserved the legacy `a3s.xml` repository format alongside the newer updater
  configuration and manifest formats.
- Improved synchronization behavior by using fresh repository metadata and
  avoiding stale local cache data.
- Restored compatibility with the compact legacy layout.

## Reliability and security

- Added SHA-256 verification for updater archives before installation.
- Hardened ZIP extraction against path traversal, absolute paths and symlink
  escapes.
- Restricted Java object deserialization to the legacy Arma3Sync model and
  approved JDK types with stream limits.
- Improved update cancellation and protected user-managed configuration.
- Repository builds retain the last valid `.a3s` metadata until a new scan has
  completed; metadata writes use temporary files and atomic replacement.
- Normalized addon path matching with directory boundaries.
- Parallel download state and error handling are synchronized; the error limit
  is applied exactly at ten errors.
- Swing UI updates are dispatched safely through the Event Dispatch Thread.
- Removed forced `System.gc()` calls from active application paths.
- Repository total-size reporting represents the complete repository content,
  not an update delta.
- Repository revisions remain unchanged when published file paths, sizes and
  SHA-1 content are unchanged.
- Selected path handling uses `Path.resolve()` and updater JSON validation is
  stricter.

## Workshop HTML export

- HTML preset writes use a temporary file, atomic replacement where supported
  and an integrity check.
- Missing or invalid Workshop IDs open the guided metadata dialog.
- Metadata scanning and validation occur before the save chooser.
- Export dialogs are attached to the visible Addons panel and diagnostics are
  written to `launcher-preset-export.log`.
- The Workshop metadata cache uses a sidecar lock and atomic replacement.

## Runtime, updates and compatibility

- The Standard Windows package bundles a reduced Java 25 runtime under
  `runtime/`; no separate Java installation is required.
- The optional Compact package requires Java 25 or newer on the target system.
- GitHub Releases can be selected as the update source and the selected source
  is passed explicitly to the updater.
- Existing repositories, profiles and the legacy `a3s.xml` format remain
  compatible.
